* Scope
=share/librewolf/chrome/userChrome.css= contains the CSS captured from this host. It hides the horizontal tab toolbar and removes browser borders. Install and configure Sidebery before applying it on a new host so that a visible tab interface remains available. =share/librewolf/extensions.json= records the six active third-party extensions observed in September 2026: uBlock Origin, Bitwarden, Sidebery, Vimium, Temporary Containers and Dark Reader. Mozilla's bundled system addons are omitted.

Extension settings are separate from extension installation. No settings exports have been captured yet. The export workflow below is required to preserve the current Sidebery customization and other addon preferences. Browser databases, profile IDs, credentials, history and session files are not managed.

* Requirements
No compilation is needed. Fedora runtime packages: =bash=, =coreutils=, =gawk= and =jq=. Validation additionally uses =ShellCheck=, =ripgrep=, =diffutils= and =just=. Running the browser requires =flatpak= and =io.gitlab.librewolf-community=. Do not install packages into the immutable host for this script; include any missing packages in the image build.

* New host
1. Install/launch LibreWolf through the usual Flatpak workflow once to create a profile.
2. Run =./bin/scripts/librewolf-config extensions= and open the listed installation URLs in LibreWolf. Confirm installation in the browser. LibreWolf may already supply uBlock Origin.
3. Import saved addon settings using each extension's own settings UI. Configure Sidebery before hiding the horizontal tabs.
4. Close LibreWolf completely.
5. Run =just librewolf-plan= to inspect the destination, then =just librewolf-apply=.
6. Restart LibreWolf. Check that Sidebery and the CSS are active. =about:config= should show =toolkit.legacyUserProfileCustomizations.stylesheets= enabled.

The script resolves its assets relative to its real executable location, including when Stow installs it through a symlink. =share/= and =docs/= are repo-only directories excluded from Stow. Browser files are copied explicitly with the apply recipe. Running =just stow= alone does not apply browser configuration. This avoids creating links into a checkout that the Flatpak sandbox cannot read.

* Profile discovery
The script looks for =profiles.ini= under =~/.var/app/io.gitlab.librewolf-community/config/librewolf/librewolf=, then the legacy =~/.var/app/io.gitlab.librewolf-community/.librewolf=. An explicit =--root= overrides those roots, and =--profile= selects an initialized profile directly.

An install-specific =[Install...]= default takes priority over a legacy =[Profile...]= default. Multiple distinct installation defaults, multiple profile defaults, or multiple profiles with no default cause an error requiring =--profile=. Relative and absolute profile paths are supported. The script requires =prefs.js= as evidence of an initialized profile. It does not create or choose a new browser profile.

* CSS edits, backups and rollback
Edit =share/librewolf/chrome/userChrome.css= and reapply after closing the browser. If CSS was edited inside the live profile, run =just librewolf-capture= to copy it back into the repository. Capture is read-only toward the browser and replaces only the managed CSS file, with numbered backups.

Apply preserves unrelated =user.js= content and replaces its own delimited preference block. Changed destinations receive GNU numbered backups such as =user.js.~1~= and =chrome/userChrome.css.~1~=. Identical files are left alone, making repeated application idempotent. Symlinked destinations and existing profile locks cause refusal. Stale locks require manual inspection; the script never deletes them. Keep the browser closed for the entire apply operation.

To roll back, close LibreWolf and restore the desired numbered backups, or remove the managed CSS and the delimited block from =user.js=. A preference already loaded into =prefs.js= remains set until changed through =about:config=; deleting the block alone does not reset it. A failure after one file is copied can leave a partially applied setup; backups are per file, not a transaction across both files.

* Extension settings
Use native exports because Firefox extension storage contains host-specific internal identifiers and potentially private data. Do not copy =storage/=, =prefs.js=, =extensions.json= from the profile, or IndexedDB files into git. The managed extension inventory is a deliberately reduced list of names, IDs and public installation URLs.

For Sidebery, open Settings and use its export controls to include settings, styles, panels/navigation and menus. Exclude tab snapshots and other browsing state. Save the JSON into =~/Downloads=, which the Flatpak can access. Then run:

#+begin_src bash
./bin/scripts/librewolf-config save-export sidebery ~/Downloads/sidebery-settings.json
#+end_src

For uBlock Origin use its dashboard settings backup; for Vimium use its options backup; for Dark Reader and Temporary Containers use the export functionality offered by the installed version. The same command accepts =ublock=, =vimium=, =darkreader= and =temporary-containers=. Only JSON object exports are accepted. The script validates JSON syntax and allowed addon names, not each addon's schema, and does not redact content automatically. Review custom URLs, rules, container names and other personal information before committing. Never export a Bitwarden vault into this repo; authenticate separately on each host.

Import the resulting =share/librewolf/exports/NAME.json= through the matching addon UI. If the Flatpak file chooser cannot see the checkout, copy the desired export into =~/Downloads= temporarily and import that copy. No filesystem override is needed. The command does not automate browser UI, install extensions or inject settings into a running browser. Update =extensions.json= when adding/removing addons; the =extensions= command lists public latest-version XPI URLs without pinning old binaries.

* Verification and maintenance
Run =just test-librewolf=, =bash -n bin/scripts/librewolf-config tests/scripts/test-librewolf-config.sh= and =shellcheck bin/scripts/librewolf-config tests/scripts/test-librewolf-config.sh=. Fixtures cover install-default precedence, spaces, absolute profiles, preview behavior, backups, repeated apply, unrelated preferences, locks, ambiguous defaults, missing arguments and malformed managed blocks. These checks do not launch the real browser or verify visual appearance or native export imports. The existing =just test= target remains the Qtile check.

Future extensions should add native-format validation only when an actual export is available. Do not claim that a recorded installation URL also backs up addon preferences. If LibreWolf changes its profile layout, update the discovery fixtures with an observed =profiles.ini= sample before changing the parser.
